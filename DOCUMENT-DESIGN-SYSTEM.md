# ZANA POS — UNIFIED DOCUMENT DESIGN SYSTEM (UDDS)

**Version:** 1.0.0  
**Specification Level:** Production Commercial Standard (Stripe / Shopify / Xero / QuickBooks parity)  
**Scope:** Commercial Invoices, Financial Statements, Business Reports, Purchase Vouchers, Inventory Catalogs, and Barcode/QR Labels  
**Non-Negotiable Boundary:** **THERMAL RECEIPTS REMAIN UNTOUCHED** (Existing thermal 58mm/80mm receipt templates, ESC/POS byte streaming, and Bluetooth receipt drivers are strictly preserved).

---

## 1. DESIGN PHILOSOPHY & BRAND IDENTITY

The Zana POS document design philosophy follows modern enterprise SaaS reporting principles:
- **Clarity Over Decoration:** Clean, high-contrast layouts on pure white backgrounds (`#FFFFFF`). Zero gratuitous gradients, heavy shadows, or decorative borders.
- **Visual Restraint & Intentional Brand Accents:** Subtle use of Zana's signature Terracotta brand color (`#784421`) for primary dividing rules, active status indicators, and total highlights. Neutral slate (`#0F172A`) for dominant typography.
- **African SME Business Context:** Native support for East African commercial reporting conventions, including:
  - Multi-currency formatting (default `KES` / `KSh`, with dynamic support for `UGX`, `TZS`, `USD`).
  - Kenya Revenue Authority (KRA) PIN and Tax Invoice compliance.
  - M-Pesa transaction reference rendering (e.g., `QHK48929LZ`).
  - Nairobi Timezone (UTC+03:00) standard timestamps (`DD MMM YYYY, HH:mm`).
- **Complete Format Parity:** Whether exporting as PDF, XLSX, CSV, or printing via browser driver, the underlying business data, dates, filters, calculations, and column semantics must be 100% consistent.

```typescript
  shopName: string;              // e.g., "SokoSafi CBD Main Branch"
  branchName?: string;           // e.g., "Moi Avenue Store"

  email: string;                 // e.g., "billing@sokosafi.co.ke"
  kraPin?: string;               // e.g., "P051234567Z"
  vatRegistered: boolean;        // If true, header renders "TAX INVOICE"
  taxRate: number;               // Standard VAT rate (e.g., 16)
  taxInclusive: boolean;         // Pricing mode
  currency: string;              // Currency code (e.g., "KES")
  currencySymbol: string;        // Symbol (e.g., "KSh")

```

> [!IMPORTANT]
> **No Hardcoded Business Names:** No template may hardcode `"Default Shop"` or `"Zana POS"` as the company name. If a field is empty, fallback gracefully to the authenticated shop's verified profile.

## 5. REUSABLE DOCUMENT TEMPLATES

The Unified Document Design System defines standard blueprints for every document category:

### Template 1: Financial & Analytical Business Reports
- **Target Modules:** `/reports` (Sales Trend, Profit & Loss, Tax Estimate, Shifts, Cashier Summaries), `/financial-analysis`.
- **Layout:**
  - Header: Store Identity + Report Title + Generation Timestamp.
  - Filter Banner: Date Range, Store/Branch Filter, Cashier Scope.
  - KPI Summary Block: 3 or 4 metric cards (Gross Revenue, COGS, Net Profit, Tax Liability).
  - Main Data Table: Strict column widths, formatted currency, alternating zebra stripes.
  - Totals Row: Bold background `#F1F5F9`, double top-border.
  - Footer: Multi-page numbering `Page X of Y`.

### Template 2: Commercial Sales Invoice & Credit Note
- **Target Modules:** `/invoices`, `/sales/invoice`.
- **Layout:**
  - Official header with KRA Tax Invoice designation when applicable.
  - Bill To block with Customer Name, Phone, and Tax PIN.
  - Itemized table with Product Name, SKU, Quantity, Unit Price, Tax, and Line Total.
  - Financial Summary block right-aligned with Subtotal, Discount, Tax, Grand Total, and Balance Due.
  - Payment Details: Method (Cash, M-Pesa with transaction reference, Bank Transfer, Card).

### Template 3: Procurement & Receiving Vouchers
- **Target Modules:** `/purchases` (Receiving Voucher), `/purchase-orders` (Formal PO).
- **Layout:**
  - Vendor / Supplier block (Supplier Name, Contact Person, Phone, Email).
  - Items with Supplier SKU, Received Qty, Agreed Unit Cost, Subtotal.
  - Official Dual-Signature Block: "Authorized Purchasing Officer" and "Storekeeper / Receiver Signature".

### Template 4: Customer & Supplier Account Statements
- **Target Modules:** `/customers` (Statements), `/suppliers` (Statements).
- **Layout:**
  - Statement Period (e.g., "01 Jan 2026 to 31 Jan 2026").
  - Opening Balance.
  - Chronological Ledger: Date, Transaction Type (Invoice, Payment, Refund, Return), Reference #, Debit, Credit, Running Balance.
  - Closing Outstanding Balance.
  - Payment remittance bank/M-Pesa paybill instructions.

### Template 5: Inventory Valuation & Catalog Reports
- **Target Modules:** `/products`, `/manage-stock`.
- **Layout:**
  - Grouping by Category.
  - Columns: SKU, Barcode, Product Name, Unit Cost, Selling Price, In Stock, Reorder Point, Stock Valuation (Cost × Qty), Margin %.
  - Category subtotals and Grand Total Inventory Valuation.

### Template 6: Barcode & QR Label Printing Sheets
- **Target Modules:** `/print/barcode`, `/print/qr`.
- **Layout:**
  - Supports continuous roll (50mm × 25mm, 40mm × 30mm) for thermal label printers.
  - Supports standard A4 sticker sheets (38-up, 24-up, 21-up).
  - Label contents: Store Name, Product Name (truncated to 24 chars), Barcode / QR Graphic, Price in bold currency (`KSh 450.00`).

## 6. FORMAT-SPECIFIC IMPLEMENTATION RULES

### 6.1 PDF Implementation Rules (`jspdf` + `jspdf-autotable` & `pdfkit`)
1. **Dynamic Page Breaks:** No document may assume a fixed page height. Footers must be placed dynamically or inside `didDrawPage` handlers.
2. **Repeated Headers:** Multi-page tables must repeat column headers on subsequent pages automatically.
3. **Selectable & Searchable Text:** Fonts must embed standard character maps. No rasterized text snapshots.
4. **Proper Pagination:** Every page must render `Page X of Y` in the bottom right corner.
5. **Logo Rendering:** If a store logo is configured, embed as high-resolution PNG/JPEG with clamped dimensions (max width 120pt, max height 50pt) preserving aspect ratio.

### 6.2 Excel / XLSX Implementation Rules (`xlsx` / `ExcelJS`)
1. **Semantic Cell Types:** Numeric figures must be stored as numbers (type `n`), not strings, so Excel formulas (`SUM`, `AVERAGE`) work immediately.
2. **Cell Number Formatting:** Format monetary cells with `#,##0.00` or `[$KSh] #,##0.00`.
3. **Auto-Fitted Column Widths:** Compute column width dynamically based on maximum cell content length + 3 padding characters. Minimum column width: 12 chars.
4. **Frozen Header Panes:** The first row (headers) and title block must be frozen (`views: [{ state: 'frozen', ySplit: 4 }]`) so headers remain visible when scrolling.
5. **Formula Row:** Totals must use `=SUM(E5:E25)` rather than static calculated values where applicable.

### 6.3 CSV Implementation Rules
1. **RFC 4180 Compliance:** Any field containing commas (`,`), double quotes (`"`), or newlines (`\n`) must be enclosed in double quotes. Double quotes inside fields must be escaped as `""`.
2. **UTF-8 BOM:** Prefix file buffers with `\uFEFF` (Byte Order Mark) to ensure Excel opens UTF-8 characters without encoding corruption.
3. **Clean Date Formatting:** Dates formatted as `YYYY-MM-DD` or `YYYY-MM-DD HH:mm:ss` for reliable sorting and database import.

### 6.4 Browser Print Implementation Rules (`@media print`)
1. **Strict Print Isolation:** All print views must render inside a scoped container (`#printable-document-area`).
2. **Zero Screen Pollution:** No inline `<style>` tags with `body * { visibility: hidden }`. All print rules must be defined in `index.css` scoped to `body:has(#printable-document-area)`:
   ```css
   @media print {
     body:has(#printable-document-area) * {
       visibility: hidden;
     }
     #printable-document-area,
     #printable-document-area * {
       visibility: visible;
     }
     #printable-document-area {
       position: absolute;
       top: 0;
       left: 0;
       width: 100%;
       margin: 0;
       padding: 0;
     }
   }
   ```
3. **Hide Interactive UI:** Automatically hide `.no-print`, `button`, `nav`, `aside`, and scrollbars during print.
4. **Table Pagination:** Set `tr { break-inside: avoid; page-break-inside: avoid; }` to prevent table rows from splitting across page boundaries.
